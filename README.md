# 中药不良反应信号核查后端

处理跨机构中成药不良反应报告的药物警戒后端。解决的核心矛盾：**多家机构报告同名中成药致肝功能异常，但存在缺批号、转院重复上报**——贸然合并会夸大信号，直接去重又可能漏掉病程进展。

系统保存原始报告，只生成**可能重复组**交人工判定；随访只追加不改写首报；同名药按厂家/批准信息分开聚合；批号缺失保留"未知"不猜测；严重性重判全程留痕；达标信号进入可幂等驱动的调查流程；可识别信息仅授权角色可见。

## 运行

```bash
python3 -m unittest discover -s tests -v   # 22 个测试
python3 -m demo                            # 端到端可解释样例
python3 -m compileall safety               # 契约编译检查（Python 3.11）
```

## 模块结构

| 模块 | 职责 |
|---|---|
| `safety/contracts.py` | 病例版本、暴露、产品身份、信号、重复组、严重性判定、时间线等不可变契约 |
| `safety/config.py` | 信号阈值（病例数/时间窗）、严重性规则及规则版本 |
| `safety/privacy.py` | 原始伪标识带盐哈希派生匹配标识；事件术语规范化 |
| `safety/access.py` | RBAC：仅 `pv-physician`/`privacy-officer` 可查看可识别信息 |
| `safety/repository.py` | 内存存储：原始报告冻结、身份分区隔离、版本只追加、病例别名合并 |
| `safety/ingest.py` | 报告接收：冻结快照、独立建案、随访追加（不覆盖首报）、批号留空 |
| `safety/linkage.py` | 可能重复组检测与人工判定（合并/保持独立，终局留痕） |
| `safety/seriousness.py` | 严重性重新判定：规则版本+命中术语+复核人+前后级别 |
| `safety/signals.py` | 按产品身份聚合、阈值检测、调查状态机与幂等启动 |
| `safety/reports.py` | 可解释输出：病例簇、产品趋势、调查时间线、信号→原始报告回溯 |

## 关键设计决策

**1. 隐私保护下的匹配，不自动并案。** 机构提交的 `privacyKey` 只存入独立身份分区，业务链路只持有带盐哈希 `pmk:*`。标识一致→强线索；双方都有标识却不同→即使事件/产品/时间全吻合也绝不聚组（不同患者）；仅在标识缺失时才用"事件+时间+同一产品身份"三项软线索提示。所有组都是 `pending`，由授权人员判定 `merged` 或 `keep-independent`，结论终局，记录判定人与理由。

**2. 合并通过版本追加实现，首报永不覆盖。** 确认合并后，成员病例的报告按时间转为主病例的后续版本（`follows_version` 串链），主病例 v1 首报原对象不变；每份原始报告快照仍可独立回溯。

**3. 信号计数不夸大也不漏报。** 按 `产品名|厂家|批准文号` 身份分桶（缺失值显式为"未知"，不猜测补齐）；已合并组计 1 例，已判定独立的分别计数，**未判定组保守折为 1 个待核单位**并在信号详情标注，待人工结论后口径才落定。

**4. 批号与原料批次。** 取不到批号存 `None`，产品趋势中单列 `unknown_lot_reports`，绝不与已知批号混算或编造；质量调查阶段针对具体产品批号（如 `lot-8`）与原料批次（如 `ing-huangqin-22`）挂账追查。

**5. 严重性可回溯。** 每次重判生成不可变记录：规则 ID 与版本（`hepato-v1`）、命中术语、前后级别、复核人、理由；支持授权人工复核覆盖，同样标记为 `MANUAL` 留痕。

**6. 调查幂等与状态机。** `validating → follow-up → quality-review → closed`，每次流转写时间线。相同幂等键重复请求返回同一调查；即使换键或不带键，同一信号也无法启动第二次。关闭后不可再流转。

## 样例输出

`python3 -m demo` 对 `fixtures/adverse_reports.json`（a/b 为同一患者 `p-71` 转院、b 缺批号，c 为同名但厂家 `maker-b` 的另一患者）并追加两名同身份患者，依次产出：脱敏原始报告 → 可能重复组及依据 → 人工合并后的可解释病例簇（首报保留+随访链）→ 病程进展触发的严重性上调 → 分开的产品趋势（未知批号如实挂账）→ 达标信号 → 幂等调查时间线 → 从信号回溯每份原始报告 → RBAC 拒绝/放行与访问留痕。
