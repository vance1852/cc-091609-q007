# 中药不良反应信号核查后端

整理中成药不良反应的**病例首报与随访版本、产品暴露、疑似重复、严重性复核、
产品趋势与信号调查流程**。患者匹配标识与可识别信息分开保存，疑似重复只作为
人工核查线索。

## 设计原则

1. **原始报告不可变**：报告只追加进哈希链台账（SHA-256 原文哈希 + 前序哈希），
   重启重放时校验；随访只在同一病例下新增 `CaseVersion`，首报永不被覆盖，
   重复 `report_id` 拒绝写入。
2. **隐私匹配**：上报方隐私标识经 HMAC-SHA256 加盐派生不可逆匹配标识
   （`privacy.py`，盐从部署环境注入），只用于链接，不暴露原文。
3. **疑似重复只给线索**：按匹配标识(0.70)+事件族(0.15)+机构(0.05)+时间邻近
   (0.10) 两两评分，超阈值的病例用并查集聚成疑似组，附评分依据；由人工确认
   **合并**（指定主病例）或**保持独立**，决定落审计且不可重复决定。
4. **产品身份分开聚合**：聚合键 = 药名 + 厂家 + 批准信息；同名药厂家/批准不同
   不合并。批号缺失保留“未知”，不猜测、不与已知批号混淆；原料批次随暴露上卷。
5. **严重性重新判定**：按 S-EV01/02/03 规则映射术语，多版本取最高等级，
   判定记录**规则条文 + 复核人 + 时间**，历史全部保留。
6. **信号流程**：`validating → follow-up → quality-review → closed`，
   状态只能顺序前进；进入质量调查必须显式指定受调查的**产品批号与原料批号**
   （含“未知”），关闭必须填理由。
7. **幂等启动**：以（产品身份键, 规则版本）为请求键，重复请求直接返回既有信号，
   绝不启动两次调查。
8. **RBAC**：只有 `case-investigator` / `admin` 可查看可识别信息；其他角色
   看到机构、隐私键、原文中的可识别字段全部脱敏；强授权接口未授权即拒绝。
9. **双向溯源**：从信号可展开到每份原始报告（含被合并病例保留的各版本），
   每个调查动作构成带操作人/批次对象的可解释时间线。

## 模块

| 文件 | 职责 |
|---|---|
| `safety/contracts.py` | 病例版本、暴露、信号契约（未改动） |
| `safety/config.py` | 阈值、规则版本、匹配权重、角色与严重性规则 |
| `safety/privacy.py` | HMAC 匹配标识派生、批号“未知”处理、访问控制 |
| `safety/store.py` | 原始报告只追加哈希链台账、病例版本构建、重放校验 |
| `safety/matching.py` | 疑似重复评分聚类与人工合并/独立确认 |
| `safety/severity.py` | 严重性规则映射与复核留痕 |
| `safety/aggregation.py` | 按产品身份聚合趋势、批号/原料批上卷 |
| `safety/workflow.py` | 信号阈值启动、幂等、状态机、质量批次、时间线、RBAC 溯源 |
| `safety/demo.py` | 端到端样例 |

## 运行

```bash
python3 -m compileall safety      # 契约编译检查
python3 -m safety.demo            # 端到端样例
python3 -m unittest discover -s tests -v
```

`fixtures/adverse_reports.json` 在原三条报告基础上补充了转院重报、真实随访链、
跨机构同批号与原料批数据，使样例形成信号。生产部署时 HMAC 盐必须从环境变量/
密钥管理注入，禁止使用 demo 中的固定盐。
